# Prime Continuim implementation status

This repository is a Phase 0/Phase 1 protocol and desktop-UI foundation for the seamless-remote specification, plus isolated Phase 3A security and relay primitives. It is not a production remote-agent release, and production resident commands that invoke a real provider are not authorized. On a release-attested local host, the native desktop can choose a workspace and provision a durable Prime Agent thread through client-owned escrow; exact projection publication gates the first Prompt/Stop capability. Focused Store/adapter/gateway/service/main/renderer suites verify provisioning and explicit End, including crash recovery, safe folder reselection, stale reviewed-cursor rejection, uncertainty, and no mutation replay. The credential-free release lifecycle smoke drives the one Prime Agent runtime through model selection, Prompt, Stop, restart, and End without user credentials or provider network. The former separate Codex app-server preview and companion are retired: ChatGPT subscription OAuth now configures Prime Agent's own `openai-codex` provider. Remote SSH installation and upgrades, cross-host handoff, relay connectivity, and mobile control remain deferred and fail closed. Packaging has been verified only as an unsigned Windows x64 development artifact; macOS and Linux packaging have not been verified.

The final Windows target is now configured as explicit x64 NSIS with a one-click per-user scope, pinned installer/uninstaller icon and display name, desktop and Start menu shortcuts, launch-after-finish, and retained app data on uninstall. `pnpm dist` requires the exact configured installer artifact to be a stable regular PE file with a nonempty overlay, streams its SHA-256 without executing it, and writes a standard sibling `.sha256` file. This development artifact is intentionally unsigned, its artifact gate does not prove installed behavior or publisher authenticity, its external hostd is not covered by ASAR integrity, and it is not a production-ready or hostile-tamper-resistant distribution.

## Deferred production capabilities and release gates

- Remote SSH installation is a consent-bearing, non-executable plan. A signed, checksummed host-service installer/upgrader is not bundled, and no remote install command is executed by this build.
- The Windows development installer has no signed publication channel or automatic updater. Its real install, same-version repair, version upgrade, shortcut, running-hostd handoff, data-retention, and uninstall behavior still require isolated lifecycle E2E coverage before release; the checksum-only final-artifact gate deliberately does not execute setup or claim publisher authenticity.
- Authenticated Prime Agent `openai-codex` browser sign-in and a real resident provider turn have not been run or cited. The opt-in installed-candidate harness now encodes sign-in, refreshed model availability, exact selection, long Prompt/stream/Stop, orderly desktop plus owned-hostd restart, exact-envelope reconciliation without direct harness submission, stable durable/provider-dispatch non-replay observation, End, and cleanup, but its mere existence and source tests do not satisfy this gate. Remote/headless OAuth remains unavailable until Prime Agent exposes an independently reviewed device-code or equivalent host-bound flow.
- A future Unix upgrader must stop every older lock-unaware hostd before starting this version. Empty ownership remnants intentionally fail closed and require bounded recovery guidance; mixed-version processes do not share the new sidecar fence.
- An interactive OpenSSH askpass bridge is not implemented. Existing system OpenSSH agent/key configuration can be used; password prompts are not surfaced by this desktop build.
- Native setup authorizes only concrete aliases discovered from OpenSSH configuration. Arbitrary hostname/user entry is not exposed until the desktop control contract can grant that target explicitly.
- Fresh local resident provisioning and explicit End are implemented behind `resident_lifecycle_v1`. The native picker gives only main/hostd the folder path; HostStore durably bootstraps canonical project/workspace/thread/generation authority before Prime Agent mutation; the coordinator uses `client_owned` creation, candidate escrow, one-way promotion, and stable projection publication before activating command capability. The path-free main ledger and renderer recovery surface reconcile restart, missing status, safe exact-folder reselection, definitive cleanup, committed projection refresh, and terminal quarantine without replaying create or promote. End is path-free and bound to the exact reviewed source cursor: cursor drift rejects before lifecycle WAL or side effects, while an admitted exact binding receives one-shot kill authority only after its ending record revokes command capability. A definitive acknowledgement preserves terminal task outcome and history, emits the exact public ended disposition, retires the binding and lineage, and returns the same completed result across restart; an uncertain post-invocation result remains quarantined and is never replayed. The legacy foreground RPC gateway remains diagnostic/fallback only because it owns and can complete its client-created session.
- Verified resident readiness and proof scheduling are isolated per exact binding. Healthy threads retain Prompt, Stop, and acknowledged-idle reconciliation while unrelated bindings fail, attach, disappear, or are replaced; removed and superseded prepared connections detach independently, and stale deferred attachments cannot publish. The public command capability remains an aggregate host signal, so each command still requires the selected thread's exact live binding. Provisioning lifecycle failures have durable path-free recovery/quarantine records, but a quarantined or genuinely uncertain operation deliberately has no automatic unlock or retirement path. Failed pre-existing attachments also retry on later health polls without a bounded per-binding backoff policy. Those operator-recovery affordances remain required before production-scale multi-session control.
- Resident uncertainty retains its exact structured diagnostic beside the non-replayable desktop outbox barrier, and exact idle proof retires both. The renderer intentionally limits its global Attention projection to the newest 20 durable diagnostics, however, so an older still-active barrier can fall back to generic recovery copy under sustained multi-thread uncertainty. Before production-scale control, active resident diagnostics must be protected for the lifetime of their barrier or selected-thread lookup must bypass that presentation cap.
- A settled uncertain prompt or Stop still has no safe automatic recovery in the pinned Prime Agent 0.7.1 protocol. Its upstream `retry_worker` fix clears stopped/tombstoned descriptor state only when that operation is explicitly invoked; Continuim does not invoke `retry_worker` automatically, and the operation is not a cross-client admission/quiescence fence. `abort` and `waitForIdle` are not ordered against an older cross-client prompt preflight, while an abort whose transport outcome was lost may execute later and cancel newly admitted work. These barriers therefore remain non-replayable and nonretryable across restart. Safe operator recovery requires a future daemon-level atomic `abort_and_quiesce` epoch that covers admissions and pending preflights, or a verified session-rotation transaction that proves the old session can no longer mutate.
- The packaged-runtime initialization smoke still proves attested installation and model-catalog discovery with zero resident bindings. The release resident-lifecycle smoke now covers production client-owned escrow creation and promotion, credential-free deterministic model selection/Prompt/Stop execution, restart attachment, stale-consent rejection, explicit End, terminal projection, and no replay. The new optional installed-provider harness intentionally provisions through the production host protocol and forbids tools in its live prompt, so native picker-to-host lifecycle and authenticated coding-tool mutation/reduction remain separate unproved gates. Before external release, those gates and an actually run, reviewable real-provider receipt must be completed; source presence is not execution evidence.
- The verified runtime is now promoted from a packaged seed into a private installed development runtime, not an installed production-authorized runtime. Its embedded attestation deliberately says `development-integrity`: the outer artifact is unsigned, ordinary Node filesystem APIs cannot establish a race-free Windows reparse-point trust boundary, and same-user hostile modification is outside this checkpoint's assurance. The integrity manager rejects unsafe/ambiguous Windows names, links, extra files or directories, digest/tree/ABI drift, malformed pointers, corrupt finals, and uncertain publication; it copies only attested files into private staging, re-verifies before content-addressed publication or pre-use checks, recovers bounded crash leftovers, atomically rolls between exact attested images while retaining prior installs, and returns a frozen identity with no renderer-visible filesystem paths. Because an unsigned schema-valid prior pointer cannot be distinguished from same-user edits, rollover never dereferences it and is authorized only by the new build's embedded attestation plus exact seed; production transitions still require signed predecessor metadata. Repeated built-hostd smokes on August 6, 2026 returned initial health within the 3-second per-request gate and reached readiness within the 180-second gate; clean-promotion timing varied materially with storage and provider state, while restart re-verification retained the identical path-free identity. These observations are diagnostic, not release promises. Hostd keeps that work off its listener/health critical path; the desktop now polls and presents readiness, classifies a legacy hostd as `not_reported`, and package smoke uses the same production polling path. Fresh acquisition verification produces the opaque host-only handle consumed by runtime startup. A packaged native picker-to-host lifecycle E2E, authenticated real-provider and coding-tool mutation/reduction proof, code signing, a hostile same-user trust boundary, macOS/Linux, and additional architectures remain fail-closed release gates.
- The immutable upstream v0.7.1 release used by this checkpoint has a confirmed packaging defect in its Node distribution: the Amazon Bedrock provider references a bundle chunk that is absent from the official tarball. Digest verification correctly proves which bytes were installed, but cannot prove that every optional provider is operational. Amazon Bedrock therefore remains unsupported for this pin, and future runtime promotion requires provider-aware artifact smoke tests in addition to tree verification and daemon compatibility checks.
- Only `prompt`, `abort`, and the narrower `model.select` path have resident dispatch state machines. `steer`, `follow_up`, and `approval.resolve` remain rejected by the verified resident gateway until they gain equally durable, non-replayable operation-specific semantics.
- Before handoff is enabled, resident dispatch and authority movement must share one serialized lease/epoch boundary, admission must require the thread's current host location, and command plus handoff receipts must reserve one exact global identity namespace. Current handoff remains unavailable, so no source/destination authority move can race this local checkpoint.
- The current desktop command-identity ledger rewrites one bounded JSON file and deliberately rejects new identities after 10,000 entries while continuing to validate known identities. Before production-scale resident execution is enabled, replace it with a crash-safe indexed or sharded store that preserves the same permanent no-reuse invariant without an O(n) multi-megabyte fsync path or a reachable lifetime ceiling.
- Prime Agent v0.7.1 exports `AuthStorageBackend` for SDK callers, but its daemon creates the default file store directly. Continuim therefore cannot honestly offer OS-keyring-only custody while keeping the pinned resident daemon unchanged. The current local path uses Prime Agent's documented plaintext `auth.json` with strict host-account filesystem protection. Moving to DPAPI, Keychain, or libsecret requires an upstream daemon-wide injected storage backend or auth RPC used consistently by resident workers. Durable OAuth attempt reconciliation across hostd and desktop restart and orphan-helper recovery also remain production hardening gates.
- The chunked snapshot path is integration-tested above the single-frame limit, including checksum corruption and out-of-order rejection. The current 8 MiB ceiling is deliberately aligned with shipped host/cache/process limits. Raising it to the specification's 50 MiB requires renderer/process stress evidence, file-backed reassembly, replay-from-cursor, transfer cancellation, pause/resume, bulk-channel preemption, and p50/p95/p99 release thresholds.
- Resident projection publication still writes a bounded full public snapshot plus catalog and lineage transaction at each accepted quiet boundary. Near-limit 8 MiB/2,000-message sustained-event write-volume and event-loop benchmarks, followed by block/delta storage if needed, are required before describing this path as token-live or fleet-scale.
- Native transport currently authorizes one active host target at a time. The v3 cache does retain bounded, separately stored per-host catalogs/snapshots and the renderer builds an authority-checked offline cross-host catalog, but only one host can be live and command-authoritative. Concurrent host transports, aggregate live-state semantics, resource bounds under many active hosts, and cross-host control verification remain Phase 1 gates; switching the active host must not be mistaken for production multi-host continuity.
- Cross-host handoff is unavailable. Handoff schemas and the isolated store harness cover verified clean durable checkpoints, but native cross-host commit is blocked. Before enabling it, command and handoff receipts must share one reserved `(deviceId, commandId)` namespace and every duplicate handoff must match the originally recorded handoff command exactly. Repository identity negotiation, Git object transfer, dirty/untracked state transfer, destination worktree materialization, and cross-host rollback coordination remain Phase 2.
- Native notifications remain deferred.
- Relay connectivity and mobile control are unavailable and have no desktop entry point. The desktop's exact completed-receipt reconciliation remains device-local, and host framed projection/proof signals remain suppressed on relay sessions. The new polling-only host control projection lets a future independently authenticated device observe another command envelope's current Prompt/Stop ownership without consuming that device's outbox; it does not create a relay, authenticate a phone, submit Stop, or replace exact command admission. This build creates no QR code, matching code, credential, listener, production relay session, or mobile command.
- Unix ownership races are covered by direct filesystem contention tests on the current Windows development host; real Unix-domain-socket/process integration must still pass in Linux and macOS CI before a cross-platform release.
- Real phone control remains Phase 3B: the cross-platform TLS-vs-Noise architecture spike and recorded lock decision, a reviewed crypto provider and application E2EE handshake, replay/sequence protection, private host/device key generation and OS-backed storage, human pairing confirmation, outbound host/desktop relay integration, durable multi-node relay grant issuance, compatibility handling, production channel lifecycle telemetry, and a packaged native mobile client must all be implemented and adversarially verified.
- Managed-compute adapters and later collaboration work remain Phases 4–5.

The Phase 0/Phase 1 protocol/UI foundation, crash-safe local resident provisioning and continuity checkpoint, and isolated Phase 3A seams are suitable for controlled development testing. The specification's production remote-release checklist is not satisfied. Production authorization, packaged provider-backed execution, uncertainty/quarantine operator recovery, remote SSH install/upgrade, cross-host handoff, relay connectivity, pairing, and phone control must remain unavailable until their release gates are implemented and verified.
