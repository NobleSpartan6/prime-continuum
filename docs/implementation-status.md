# Prime Continuim implementation status

This repository is a Phase 0/Phase 1 protocol and desktop-UI foundation for the seamless-remote specification, plus isolated Phase 3A security and relay primitives. It is not a production remote-agent release, and production resident commands that invoke a real provider are not authorized. On a release-attested local host, the native desktop can choose a workspace and provision a durable resident thread through client-owned escrow; exact projection publication gates the first Prompt/Stop capability. Focused Store/adapter/gateway/service/main/renderer suites verify provisioning and explicit End, including crash recovery, safe folder reselection, stale reviewed-cursor rejection, uncertainty, and no mutation replay. The credential-free release lifecycle smoke starts an empty attested hostd, drives production `resident.provision` through HostService, the gateway, the coordinator, and the isolated Worker, selects an isolated deterministic extension model, executes three Prompt calls and two Stops, proves exact receipts/projections/replay suppression across restart, and completes explicit End recovery after deterministic response loss. It reads no user credential and uses no provider network; it is not a real provider-authentication or coding-tool E2E. Remote SSH installation and upgrades, cross-host handoff, relay connectivity, and mobile control remain deferred and fail closed. Packaging has been verified only as an unsigned Windows x64 development artifact; macOS and Linux packaging have not been verified.

## Implemented and verified in development

- A canonical `pnpm self-build` candidate-evaluation command serializes through the existing physical-worktree lock and supervised child-tree lease, captures and re-fences exact `HEAD`/dirty/untracked/full-tree identities, rejects links and code-owned private/generated paths independently of mutable ignore rules, and copies the complete regular-file manifest into a detached no-checkout worktree. It uses a sanitized environment and offline frozen copy-import dependency tree local to the evaluation, then runs typechecking, tests, exact runtime verification immediately before and after `build:release`, and release-artifact digesting. A capped no-replace receipt binds those inputs, full tool/runtime identities, command outcomes, and artifact digests; its SHA-256 detects changes but does not authenticate them. The candidate controls the invoked package scripts and policy, so this is build-readiness correlation—not an independent evaluator, malicious-candidate filesystem boundary, security sandbox, provider-backed recursive evaluator, autonomous promotion, package/installer gate, signing result, or cross-platform release proof.

- One Electron/React project-and-thread shell that can project local and configured SSH-backed locations. A projected location does not imply that production resident command execution, remote installation, or handoff is available.
- One optional singleton desktop HUD for an exact attached resident host/thread/generation. Its expanded surface reuses the authoritative transcript and Prompt/Stop composer; its draggable buddy is only a compact projection of that same thread. Native IPC distinguishes the trusted workbench and HUD main frames, fans service events to both, and role-gates window controls. Explicit close destroys the overlay; only bounded geometry and the last chosen buddy/expanded mode persist, never open state, target, path, draft, or conversation data. This is an independent always-on-top companion, not target-app docking, window inspection, a second agent, or a separate runtime connection.
- Sandboxed renderer, context isolation, sender-validated bounded IPC, restrictive navigation and permission policy, and no renderer Node access.
- Recursive OpenSSH config discovery with concrete-alias filtering, `Include` handling, `ssh -G` resolution, and fixed argument-array process launches. Private key contents are never read.
- The same bounded, length-prefixed protocol over a user-owned local pipe/socket and SSH stdio; there is no public TCP listener.
- A persistent `prime-agent-hostd` with atomic durable catalogs, snapshots, command receipts, command/event journals, and exact-envelope idempotency rooted at `(deviceId, commandId)`. Production initialization leaves project and thread catalogs empty; test fixtures create empty-transcript workspace authority through the real durable bootstrap transaction.
- Command admission uses a bounded versioned write-ahead transaction: the exact command identity, snapshot, and catalog materialize before the receipt becomes visible, unfinished transactions recover on startup, and deterministic journal/event IDs prevent duplicate audit records. Recovery interprets old generation-optional transactions only through a private v1 schema, verifies the complete prepared catalog/journal/receipt relationship, never promotes a legacy non-model command into a replay identity, and never dispatches during recovery.
- Cache-first native startup followed by authoritative background connection, catalog refresh, and thread snapshot refresh. Bootstrap retries if a concurrent connection switch would mix authorities. The last verified run target survives a desktop restart; failed attempts cannot replace it.
- Negotiated `snapshot_chunks_v1` delivery for authoritative catalog and thread snapshots. Hostd serializes into fixed 512 KiB chunks without first building a monolithic transfer buffer, caps the currently shipped transfer at 8 MiB, hashes the exact UTF-8 bytes, and writes each frame with backpressure. The desktop permits only one retained transfer per connection and requires the exact request/method/thread/transfer identity, declaration-derived chunk count, strict order and size, canonical base64, complete byte count, SHA-256 match, valid UTF-8/JSON, and the expected projection schema before resolving the request; partial, cross-thread, or corrupt transfers close the connection and never replace the cache.
- A reversible `ReliableRelayByteTunnel` seam now conformance-tests the relay semantics a future TLS channel needs: monotonic routing message IDs, bounded fragmentation/read buffering, ordered socket-acceptance receipts, and terminal handling for gaps, duplicates, rejection, missing receipts, wrong channels, backpressure, EOF, and abort. It never retries uncertain bytes and never treats the relay routing ID as authenticated identity. It is not integrated with hostd, WebSocket, TLS, pairing, or mobile UI and advertises no capability.
- Transport loss retries indefinitely with bounded exponential-style backoff and jitter; connection state remains separate from task state throughout recovery.
- A durable outbox and exact-envelope reconciliation foundation remains for protocol compatibility, but the resident **Run prompt** and **Stop** controls are live-only and disabled offline; the renderer never presents a blind “send when reconnected” path for either mutation. Cache, outbox, mutations, receipts, and snapshot events are scoped to immutable `hostId`, never an alias. Every existing-thread mutation now requires the exact execution generation and one stable issue time from renderer through desktop, persistence, protocol, admission, gateway, receipt, and projection; `issuedAt` is identity/audit metadata, not trusted causal time. These stricter semantics are advertised only as `prime_agent_commands_v2`: a new desktop never enables command delivery from the legacy `prime_agent_commands_v1` capability, and an old desktop therefore cannot mistake the new host contract for its weaker one. Before persistence or send, the desktop reserves the device-global command ID in a private durable SHA-256 envelope ledger that survives terminal outbox removal. On reconnect, a waiting legacy-compatible mutation is delivered only after that same host compares the complete immutable envelope and reports that exact command unknown. Legacy, corrupt, cross-host, stale-generation, and ambiguous entries are retained locally but never blindly replayed or presented as the current generation's receipt.
- Exact-envelope reconciliation currently uses one command per read-only request to stay below the fixed one-MiB transport frame under worst-case escaping. This is safe but not the final high-latency SSH/fleet optimization; a canonical digest or byte-aware batching contract remains to be designed and verified.
- A durable single-process clean-checkpoint handoff harness for protocol, idempotency, verification, and rollback tests. Immutable checkpoints are privately written and flushed before atomic no-replace publication; recovery accepts an existing checkpoint only when its canonical bytes exactly match the deterministic plan. Production hostd reports the destination coordinator as unavailable and does not advertise executable handoff.

## Deferred production capabilities and release gates

- Remote SSH installation is a consent-bearing, non-executable plan. A signed, checksummed host-service installer/upgrader is not bundled, and no remote install command is executed by this build.
- The Windows development installer has no signed publication channel or automatic updater. Its real install, same-version repair, version upgrade, shortcut, running-hostd handoff, data-retention, and uninstall behavior still require isolated lifecycle E2E coverage before release; the checksum-only final-artifact gate deliberately does not execute setup or claim publisher authenticity.
- A future Unix upgrader must stop every older lock-unaware hostd before starting this version. Empty ownership remnants intentionally fail closed and require bounded recovery guidance; mixed-version processes do not share the new sidecar fence.
- An interactive OpenSSH askpass bridge is not implemented. Existing system OpenSSH agent/key configuration can be used; password prompts are not surfaced by this desktop build.
- Native setup authorizes only concrete aliases discovered from OpenSSH configuration. Arbitrary hostname/user entry is not exposed until the desktop control contract can grant that target explicitly.
- Fresh local resident provisioning and explicit End are implemented behind `resident_lifecycle_v1`. The native picker gives only main/hostd the folder path; HostStore durably bootstraps canonical project/workspace/thread/generation authority before Prime Agent mutation; the coordinator uses `client_owned` creation, candidate escrow, one-way promotion, and stable projection publication before activating command capability. The path-free main ledger and renderer recovery surface reconcile restart, missing status, safe exact-folder reselection, definitive cleanup, committed projection refresh, and terminal quarantine without replaying create or promote. End is path-free and bound to the exact reviewed source cursor: cursor drift rejects before lifecycle WAL or side effects, while an admitted exact binding receives one-shot kill authority only after its ending record revokes command capability. A definitive acknowledgement preserves terminal task outcome and history, emits the exact public ended disposition, retires the binding and lineage, and returns the same completed result across restart; an uncertain post-invocation result remains quarantined and is never replayed. The legacy foreground RPC gateway remains diagnostic/fallback only because it owns and can complete its client-created session.
- Verified resident readiness and proof scheduling are isolated per exact binding. Healthy threads retain Prompt, Stop, and acknowledged-idle reconciliation while unrelated bindings fail, attach, disappear, or are replaced; removed and superseded prepared connections detach independently, and stale deferred attachments cannot publish. The public command capability remains an aggregate host signal, so each command still requires the selected thread's exact live binding. Provisioning lifecycle failures have durable path-free recovery/quarantine records, but a quarantined or genuinely uncertain operation deliberately has no automatic unlock or retirement path. Failed pre-existing attachments also retry on later health polls without a bounded per-binding backoff policy. Those operator-recovery affordances remain required before production-scale multi-session control.
- Resident uncertainty retains its exact structured diagnostic beside the non-replayable desktop outbox barrier, and exact idle proof retires both. The renderer intentionally limits its global Attention projection to the newest 20 durable diagnostics, however, so an older still-active barrier can fall back to generic recovery copy under sustained multi-thread uncertainty. Before production-scale control, active resident diagnostics must be protected for the lifetime of their barrier or selected-thread lookup must bypass that presentation cap.
- A settled uncertain prompt or Stop has no safe automatic recovery in the pinned Prime Agent 0.7.0 protocol. `abort` and `waitForIdle` are not ordered against an older cross-client prompt preflight, while an abort whose transport outcome was lost may execute later and cancel newly admitted work. These barriers therefore remain non-replayable and nonretryable across restart. Safe operator recovery requires a future daemon-level atomic `abort_and_quiesce` epoch that covers admissions and pending preflights, or a verified session-rotation transaction that proves the old session can no longer mutate.
- The packaged-runtime initialization smoke still proves attested installation and model-catalog discovery with zero resident bindings. The release resident-lifecycle smoke now covers production client-owned escrow creation and promotion, credential-free deterministic model selection/Prompt/Stop execution, restart attachment, stale-consent rejection, explicit End, terminal projection, and no replay. Before external release, a packaged native picker-to-host lifecycle E2E and an authorized real-provider E2E must exercise Prompt, Stop, model selection, coding tools, and End after authenticated execution, observe their authoritative reductions, restart hostd, and prove that no mutation is replayed.
- The verified runtime is now promoted from a packaged seed into a private installed development runtime, not an installed production-authorized runtime. Its embedded attestation deliberately says `development-integrity`: the outer artifact is unsigned, ordinary Node filesystem APIs cannot establish a race-free Windows reparse-point trust boundary, and same-user hostile modification is outside this checkpoint's assurance. The integrity manager rejects unsafe/ambiguous Windows names, links, extra files or directories, digest/tree/ABI drift, malformed pointers, corrupt finals, and uncertain publication; it copies only attested files into private staging, re-verifies before content-addressed publication or pre-use checks, recovers bounded crash leftovers, atomically rolls between exact attested images while retaining prior installs, and returns a frozen identity with no renderer-visible filesystem paths. Because an unsigned schema-valid prior pointer cannot be distinguished from same-user edits, rollover never dereferences it and is authorized only by the new build's embedded attestation plus exact seed; production transitions still require signed predecessor metadata. Repeated built-hostd smokes on August 6, 2026 returned initial health within the 3-second per-request gate and reached readiness within the 180-second gate; clean-promotion timing varied materially with storage and provider state, while restart re-verification retained the identical path-free identity. These observations are diagnostic, not release promises. Hostd keeps that work off its listener/health critical path; the desktop now polls and presents readiness, classifies a legacy hostd as `not_reported`, and package smoke uses the same production polling path. Fresh acquisition verification produces the opaque host-only handle consumed by runtime startup. A packaged native picker-to-host lifecycle E2E, authenticated real-provider and coding-tool mutation/reduction proof, code signing, a hostile same-user trust boundary, macOS/Linux, and additional architectures remain fail-closed release gates.
- The immutable upstream v0.7.0 release used by this checkpoint has a confirmed packaging defect in its Node distribution: the Amazon Bedrock provider references a bundle chunk that is absent from the official tarball. Digest verification correctly proves which bytes were installed, but cannot prove that every optional provider is operational. Amazon Bedrock therefore remains unsupported for this pin, and future runtime promotion requires provider-aware artifact smoke tests in addition to tree verification and daemon compatibility checks.
- Only `prompt`, `abort`, and the narrower `model.select` path have resident dispatch state machines. `steer`, `follow_up`, and `approval.resolve` remain rejected by the verified resident gateway until they gain equally durable, non-replayable operation-specific semantics.
- Before handoff is enabled, resident dispatch and authority movement must share one serialized lease/epoch boundary, admission must require the thread's current host location, and command plus handoff receipts must reserve one exact global identity namespace. Current handoff remains unavailable, so no source/destination authority move can race this local checkpoint.
- The current desktop command-identity ledger rewrites one bounded JSON file and deliberately rejects new identities after 10,000 entries while continuing to validate known identities. Before production-scale resident execution is enabled, replace it with a crash-safe indexed or sharded store that preserves the same permanent no-reuse invariant without an O(n) multi-megabyte fsync path or a reachable lifetime ceiling.
- Secure in-app ChatGPT subscription authentication is unavailable in production. The local protocol and main-process browser seam above are development-only. Prime Agent v0.7.0 exports the generic `AuthStorageBackend` contract and `AuthStorage.fromStorage(...)` for SDK callers, but its public CLI/daemon `main(...)` accepts no auth-storage factory; every daemon worker still constructs the default file backend and persists plaintext `<agentDir>/auth.json`. A production path requires an upstream-supported daemon storage factory, host-owned OS-backed credential custody with verified access controls, durable OAuth attempt/receipt recovery across hostd and desktop restart, orphan-helper containment, and a renderer flow that labels ChatGPT subscription access separately from API-key billing. Headless SSH and relay sign-in remain unavailable until an independently reviewed device-code or equivalent remote-safe provider contract exists.
- The chunked snapshot path is integration-tested above the single-frame limit, including checksum corruption and out-of-order rejection. The current 8 MiB ceiling is deliberately aligned with shipped host/cache/process limits. Raising it to the specification's 50 MiB requires renderer/process stress evidence, file-backed reassembly, replay-from-cursor, transfer cancellation, pause/resume, bulk-channel preemption, and p50/p95/p99 release thresholds.
- Resident projection publication still writes a bounded full public snapshot plus catalog and lineage transaction at each accepted quiet boundary. Near-limit 8 MiB/2,000-message sustained-event write-volume and event-loop benchmarks, followed by block/delta storage if needed, are required before describing this path as token-live or fleet-scale.
- Native transport currently authorizes one active host target at a time. The v3 cache does retain bounded, separately stored per-host catalogs/snapshots and the renderer builds an authority-checked offline cross-host catalog, but only one host can be live and command-authoritative. Concurrent host transports, aggregate live-state semantics, resource bounds under many active hosts, and cross-host control verification remain Phase 1 gates; switching the active host must not be mistaken for production multi-host continuity.
- Cross-host handoff is unavailable. Handoff schemas and the isolated store harness cover verified clean durable checkpoints, but native cross-host commit is blocked. Before enabling it, command and handoff receipts must share one reserved `(deviceId, commandId)` namespace and every duplicate handoff must match the originally recorded handoff command exactly. Repository identity negotiation, Git object transfer, dirty/untracked state transfer, destination worktree materialization, and cross-host rollback coordination remain Phase 2.
- Native notifications remain deferred.
- Relay connectivity and mobile control are unavailable and have no desktop entry point. The desktop's exact completed-receipt reconciliation remains device-local, and host framed projection/proof signals remain suppressed on relay sessions. The new polling-only host control projection lets a future independently authenticated device observe another command envelope's current Prompt/Stop ownership without consuming that device's outbox; it does not create a relay, authenticate a phone, submit Stop, or replace exact command admission. This build creates no QR code, matching code, credential, listener, production relay session, or mobile command.
- Unix ownership races are covered by direct filesystem contention tests on the current Windows development host; real Unix-domain-socket/process integration must still pass in Linux and macOS CI before a cross-platform release.
- Real phone control remains Phase 3B: the cross-platform TLS-vs-Noise architecture spike and recorded lock decision, a reviewed crypto provider and application E2EE handshake, replay/sequence protection, private host/device key generation and OS-backed storage, human pairing confirmation, outbound host/desktop relay integration, durable multi-node relay grant issuance, compatibility handling, production channel lifecycle telemetry, and a packaged native mobile client must all be implemented and adversarially verified.
- Managed-compute adapters and later collaboration work remain Phases 4–5.

The Phase 0/Phase 1 protocol/UI foundation, crash-safe local resident provisioning and continuity checkpoint, and isolated Phase 3A seams are suitable for controlled development testing. The specification's production remote-release checklist is not satisfied. Production authorization, packaged provider-backed execution, uncertainty/quarantine operator recovery, remote SSH install/upgrade, cross-host handoff, relay connectivity, pairing, and phone control must remain unavailable until their release gates are implemented and verified.
