# Prime Continuim implementation status

This repository is a Phase 0/Phase 1 protocol and desktop-UI foundation for the seamless-remote specification, plus isolated Phase 3A security and relay primitives. It is not a production remote-agent release, and production resident commands are not authorized or available out of the box. The release-attested local composition now contains a narrowly fenced resident prompt/Stop checkpoint, verified through focused adapter/store/service integration tests. A separate credential-free release smoke creates one real resident binding through a harness-only adapter path, loads it through the attested Worker isolation boundary, restarts hostd, and proves exact reattachment and authoritative projection without mutating the parent process; it intentionally sends no prompt or Stop and does not exercise client-owned escrow creation or promotion. No user-facing fresh-session provisioning path exists yet. Remote SSH installation and upgrades, cross-host handoff, relay connectivity, and mobile control remain deferred and fail closed. Packaging has been verified only as an unsigned Windows x64 development artifact; macOS and Linux packaging have not been verified.

## Implemented and verified in development

- One Electron/React project-and-thread shell that can project local and configured SSH-backed locations. A projected location does not imply that production resident command execution, remote installation, or handoff is available.
- Sandboxed renderer, context isolation, sender-validated bounded IPC, restrictive navigation and permission policy, and no renderer Node access.
- Recursive OpenSSH config discovery with concrete-alias filtering, `Include` handling, `ssh -G` resolution, and fixed argument-array process launches. Private key contents are never read.
- The same bounded, length-prefixed protocol over a user-owned local pipe/socket and SSH stdio; there is no public TCP listener.
- A persistent `prime-agent-hostd` with atomic durable catalogs, snapshots, command receipts, command/event journals, exact-envelope idempotency rooted at `(deviceId, commandId)`, and explicit seed data only for demos/tests.
- Command admission uses a bounded versioned write-ahead transaction: the exact command identity, snapshot, and catalog materialize before the receipt becomes visible, unfinished transactions recover on startup, and deterministic journal/event IDs prevent duplicate audit records. Recovery interprets old generation-optional transactions only through a private v1 schema, verifies the complete prepared catalog/journal/receipt relationship, never promotes a legacy non-model command into a replay identity, and never dispatches during recovery.
- Cache-first native startup followed by authoritative background connection, catalog refresh, and thread snapshot refresh. Bootstrap retries if a concurrent connection switch would mix authorities. The last verified run target survives a desktop restart; failed attempts cannot replace it.
- Negotiated `snapshot_chunks_v1` delivery for authoritative catalog and thread snapshots. Hostd serializes into fixed 512 KiB chunks without first building a monolithic transfer buffer, caps the currently shipped transfer at 8 MiB, hashes the exact UTF-8 bytes, and writes each frame with backpressure. The desktop permits only one retained transfer per connection and requires the exact request/method/thread/transfer identity, declaration-derived chunk count, strict order and size, canonical base64, complete byte count, SHA-256 match, valid UTF-8/JSON, and the expected projection schema before resolving the request; partial, cross-thread, or corrupt transfers close the connection and never replace the cache.
- A reversible `ReliableRelayByteTunnel` seam now conformance-tests the relay semantics a future TLS channel needs: monotonic routing message IDs, bounded fragmentation/read buffering, ordered socket-acceptance receipts, and terminal handling for gaps, duplicates, rejection, missing receipts, wrong channels, backpressure, EOF, and abort. It never retries uncertain bytes and never treats the relay routing ID as authenticated identity. It is not integrated with hostd, WebSocket, TLS, pairing, or mobile UI and advertises no capability.
- Transport loss retries indefinitely with bounded exponential-style backoff and jitter; connection state remains separate from task state throughout recovery.
- A durable outbox and exact-envelope reconciliation foundation remains for protocol compatibility, but the resident **Run prompt** and **Stop** controls are live-only and disabled offline; the renderer never presents a blind “send when reconnected” path for either mutation. Cache, outbox, mutations, receipts, and snapshot events are scoped to immutable `hostId`, never an alias. Every existing-thread mutation now requires the exact execution generation and one stable issue time from renderer through desktop, persistence, protocol, admission, gateway, receipt, and projection; `issuedAt` is identity/audit metadata, not trusted causal time. These stricter semantics are advertised only as `prime_agent_commands_v2`: a new desktop never enables command delivery from the legacy `prime_agent_commands_v1` capability, and an old desktop therefore cannot mistake the new host contract for its weaker one. Before persistence or send, the desktop reserves the device-global command ID in a private durable SHA-256 envelope ledger that survives terminal outbox removal. On reconnect, a waiting legacy-compatible mutation is delivered only after that same host compares the complete immutable envelope and reports that exact command unknown. Legacy, corrupt, cross-host, stale-generation, and ambiguous entries are retained locally but never blindly replayed or presented as the current generation's receipt.
- Exact-envelope reconciliation currently uses one command per read-only request to stay below the fixed one-MiB transport frame under worst-case escaping. This is safe but not the final high-latency SSH/fleet optimization; a canonical digest or byte-aware batching contract remains to be designed and verified.
- A durable single-process clean-checkpoint handoff harness for protocol, idempotency, verification, and rollback tests. Immutable checkpoints are privately written and flushed before atomic no-replace publication; recovery accepts an existing checkpoint only when its canonical bytes exactly match the deterministic plan. Production hostd reports the destination coordinator as unavailable and does not advertise executable handoff.
- Responsive thread-first desktop UI with a two-pane default, contextual evidence inspector, real project/thread search and command palette, run location as secondary context, keyboard-operable sheets, visible focus restoration, readable offline state, forced-color support, reduced-motion handling, and touch-safe hover behavior. Negotiated host capabilities gate command delivery and thread movement; rejected commands preserve their drafts, and absent runtime telemetry renders as not reported instead of authoritative zero state.
- A same-projection, read-only Companion Preview with Attention, Threads, and Hosts views. It can be opened from **Mobile**, the command palette, or `?surface=companion`; it reads the selected thread, host, status, recaps, evidence, and activity from the existing renderer projection rather than a second cache. The unavailable-Mobile sheet uses one plain-language gate and one local-preview action instead of presenting protocol scopes or a pseudo-enabled pairing flow.
- Bounded mobile pairing/device/policy schemas and a fail-closed hostd authorization seam for future relay sessions. The durable authority owns host identity metadata, host-generated 256-bit ticket IDs, expiring single-use ticket state, server-derived device grants, scope versions, revocation, retention-based terminal-history compaction, and hash-chained audit events. Ticket reservation and device-grant commit now require provider-instance-owned, one-shot ceremony capabilities; production installs no issuer, and structural, spread, reused, or cross-provider evidence is denied before ticket lookup. Restart cancels nonterminal tickets, and only the process that wins the local endpoint can recover or mutate the authority.
- Remote dispatch accepts only an opaque in-memory channel lease created after the exact crypto-provider instance consumes its own one-shot session capability. Production installs a deny-all admission boundary; the only fake issuers live under `tests/` and each owns an isolated WeakMap. The authority snapshots and validates the provider evidence, independently matches it to the canonical relay channel and current durable host key, device key/ID, scopes, host epoch, and grant version, and closes every consumed channel that fails validation. Structural relay principals, spread clones, reused tokens, and tokens from another provider instance cannot mint a lease. Authorization releases its lock before work runs, so revocation can commit while already-admitted work finishes and blocks all later admissions.
- The secure-channel factory now requires a duplex encrypted-record wire and a strict pairing/reconnect pre-handshake policy containing only locally known values. The provider must return the actual authenticated transcript after the interactive handshake. Provisional Noise transcript schemas remain for conformance tests, but no crypto architecture, provider, private host key, pairing PSK, or application E2EE implementation is selected or bundled yet.
- Hostd has a fail-closed identity-custody checkpoint for existing authority metadata. Identity-less startup never touches the provider. Configured identity loading is time-bounded, host-bound, runtime-validated, and exact-matched without regeneration; missing, locked, inaccessible, corrupt, mismatched, malformed, or failed providers leave local/SSH service available but remote dispatch disabled. The optional health field exposes only `not_configured`, `ready` public fingerprint/epoch metadata, or bounded recovery codes—never `secretRef`, public-key bytes, private material, or backend details. The production provider remains deliberately unavailable and `relay_pairing_v1` remains absent.
- Authority replacement uses file sync, atomic rename, and POSIX parent-directory sync. An ambiguous post-rename durability result invalidates all live leases and poisons that process fail-closed until restart. Unix startup prepares a fully populated, marker-fsynced ownership candidate and atomically renames that non-empty directory into a process-lifetime sidecar before stale-socket inspection. Empty or incomplete legacy locks are never auto-deleted. The lock remains held through admitted-request drain, service shutdown, server close, and inode-checked socket cleanup so a successor cannot initialize concurrently. Channel-close rejection/timeout diagnostics are bounded and emitted to hostd stderr without touching framed stdout.
- An isolated `@prime-agent/relay-server` package implements a TLS-first, native-only WebSocket routing boundary with one-shot digest-only grants, an exact fixed binary envelope, opaque byte forwarding, no offline queue, route/connection/device/rate/backpressure bounds, and browser-Origin rejection. It is adversarially tested but intentionally not integrated with hostd, desktop capabilities, or the Companion.
- Every host request requires an explicit transport context. Hostd checks authenticated `deviceId`, granular scopes, and cross-device submit/reconcile/handoff identities before dispatch or journal admission; `thread.follow_up` cannot be used to start a new run.
- A shell-free diagnostic adapter boundary for Prime Agent's headless RPC process. RPC sessions are client-owned upstream and are not the production continuity seam.
- A host-only Prime Agent v0.7.0 resident adapter now validates the exact daemon protocol/schema/capabilities and launches the verified public CLI through an absolute runtime executable, absolute socket, explicit host-owned working directory, detached stdio-free supervisor process, and role/injection-sanitized environment. The daemon remains a user-trusted coding runtime: provider and project-tool variables from the launching hostd intentionally remain available to Prime Agent and commands it runs, so this boundary is not a credential sandbox. A Windows/x64 runtime seed is assembled from a reviewed npm 10.9.8 lock with lifecycle scripts/dev/optional packages disabled, release bytes independently SHA-256 checked, non-target ZeroMQ builds pruned, empty package-manager namespaces removed, and every shipped file content-addressed. The builder rejects unattested empty directories and performs daemon-client import/hello/shutdown in a short-lived exact-runtime helper, so its long-lived process never maps a staged native addon. The release build generates one canonical attestation only after that seed verifies, embeds the same bytes in hostd and the ASAR, and binds them to the exact Electron 43.3.0 / Node 24.18.1 / modules 148 / N-API 10 host tuple. The package verifier compares the selected pointer, raw manifest, file list, payload tree, attestation, hostd, and every built main/preload/renderer artifact to the same-run outputs; the hostd bundle hash is also bound to esbuild's recorded input graph so legitimate runtime-path metadata does not weaken the no-static-bundling gate. Verification finishes with a real packaged-Electron daemon hello and clean shutdown smoke. The upstream stable macOS/Linux installer remains a separate, user-reviewed distribution path; it is not the Continuim host-service installer and is never executed automatically by the renderer.
- A newly spawned local hostd now receives one absolute packaged/development runtime-seed path; connect-first behavior never forwards it to, replaces, kills, or competes with an existing daemon. Only the endpoint winner starts release-attested integrity work. Core store/pairing recovery remains the bounded startup gate, then hostd synchronously publishes a path-free `runtime_integrity_v1` snapshot and defers the expensive scan/copy to the next event-loop turn. Readiness reports only the exact embedded trust-anchor/target identity and qualitative phase, never a percentage, path, or raw error. Final-image and pointer visibility share an ownership-scoped publication permit; shutdown closes admission and cooperatively cancels scanning while retaining the endpoint through any admitted commit and coordinator cleanup. Ordinary atomic runtime-publication uncertainty poisons runtime setup but deliberately leaves bounded base health available. During normal teardown, the listener/sidecar remains held until admitted sessions, publication work, and service cleanup settle, so a legitimate lock-aware successor cannot initialize concurrently. When a request-admission or publication proof detects physical endpoint-ownership loss, it synchronously closes new admission and sockets, drains admitted work, closes the service, and fails the hostd process lifecycle. This is fail-closed detection, not a transactional fence against a malicious process already running as the same trusted OS user. The desktop now performs one non-overlapping, lineage-fenced health poll, atomically projects capability/readiness changes, retains only same-authority cached observations across disconnects, and renders bounded path-free recovery copy for the immutable active host. The release-attested composition also constructs the verified resident gateway and advertises commands after at least one current exact binding is prepared. Readiness, dispatch, projection publication, and Prompt/Stop proof recovery are independently fenced per thread and execution generation, so a failed sibling remains read-only without poisoning a healthy binding. Normal unattested development startup and a zero-binding fresh install keep the capability absent.
- Every runtime acquisition now performs a fresh full-tree verification plus pre/post ownership proofs and returns an opaque frozen `VerifiedInstalledRuntimeHandle`; executable, module, and CLI entrypoint paths stay host-only. Desktop submission requires the current resident command capability, and hostd independently rechecks its current runtime snapshot before gateway dispatch, so stale renderer authority cannot cross a revoked runtime boundary. Workspace authority and resident bindings are stored atomically under private host state, active bindings survive a `HostStore` relaunch, completed bindings are tombstoned, and detach → store relaunch → exact same-session reattach is integration-tested. Local Resident Continuity now durably admits prompt/abort attempts with a full-envelope identity and opaque durable generation-bound dispatch lease, persists `dispatching` before the one upstream call, and never replays ambiguous work after restart. A definitively acknowledged prompt or Stop retains its exact lock and nonterminal `running` receipt until the same attached connection crosses Prime Agent's public `waitForIdle` barrier, drains resident event work, and proves a stable exact-binding inactive projection. HostStore then commits the matching completed receipt and dedicated `resident.prompt_idle_observed` or `resident.abort_idle_observed` event before the trailing invalidation. The exact Stop proof can repair a lagging active same-cursor projection; generic same-cursor replacement remains forbidden. Restart discovery retries only the read-only proof and corrupt predecessor receipts fail closed. Uncertain prompt and Stop attempts deliberately remain durable mutation barriers: an old prompt preflight or late abort side effect may still cross the pinned daemon boundary. A separate urgent framed lane lets a valid Stop bypass blocked model work while keeping bounded in-flight requests, causal response-before-proof ordering, non-starvation under later traffic, and atomic chunk writes. Prime Agent's public prompt/abort acknowledgements are reported honestly as ownership/request acceptance, never turn completion.
- The release resident-attachment smoke uses the same attested `hostd.cjs` bundle and verified Prime Agent v0.7.0 runtime that packaging consumes. With an isolated empty agent home, it creates one real resident binding through a harness-only adapter path, explicitly closes the adapter and Worker loader, restarts hostd, reattaches through the production gateway, validates the authoritative cursor-bound projection, proves the resident survives host detach, and confirms bounded daemon shutdown. It snapshots the parent process's raw `SIGINT`/`SIGTERM` listeners plus `process.emit` and `process.reallyExit` before module load and requires exact identity after attach and loader close, freezing upstream `signal-exit` mutations inside the Worker. This smoke consumes no user credential and sends no provider prompt; client-owned escrow creation and explicit promotion are not covered.
- Resident projection publication now uses an exact-binding, cursor-lineage-fenced write-ahead transaction and emits only a tiny post-commit `thread.changed` invalidation. The desktop coalesces that hint, fetches the authoritative bounded snapshot, rejects retired cursor generations across restart, and never treats a Stop acknowledgement as proof of idle. The pinned public v0.7.0 surface can prove a quiet-boundary composite snapshot, not token-by-token atomic streaming; live projection is therefore eventual at a stable boundary.
- Renderer visual verification now runs the built UI inside real Electron at 1600×1000 plus exact 390×844 and 320×704 desktop and Companion surfaces, asserts both page and surface widths remain bounded, and persists reviewable captures under `out/visual-qa/`. It exercises the deterministic browser-preview fixture, not a native resident session, so execution E2E remains a separate release gate.
- A host-only resident model-selection checkpoint admits only an exact host, thread, execution generation, and active resident binding. It persists the exact sanitized command identity before dispatch, serializes mutations per resident session, checks the live runtime catalog, invokes `setModel` at most once, and completes only after two stable cursor-bound authoritative projections agree on the selected provider and model. Ambiguous mutation results, process restart, binding drift, or unstable reconciliation become terminal `uncertain` records and are never replayed. The verified gateway can carry this command for an already-attached binding, but the renderer still exposes the model catalog as read-only.
- A local-only host OAuth checkpoint composes the pinned Prime Agent v0.7.0 `openai-codex` provider through short-lived verified-runtime helpers. The main process owns the exact allow-listed `auth.openai.com` browser launch; the renderer receives no authorization URL, prompt, state, code, token, account identifier, or raw provider error. Host binding, provider single-flight, idempotent start, bounded expiry, cancellation, helper teardown, and `set → drainErrors → reload → getAuthStatus` confirmation are enforced. The official SSH bridge and relay cannot advertise or invoke OAuth. This composition is disabled in normal startup and requires the exact development opt-in `PRIME_CONTINUIM_ENABLE_PLAINTEXT_OAUTH_DEV=1`, because the pinned upstream release stores OAuth credentials in plaintext `auth.json`. No renderer sign-in control is shipped at this checkpoint.
- The local listener is fixed to the canonical pipe/socket derived after an existing or newly created durable data root is resolved to its physical filesystem spelling; Windows junction and Unix symlink aliases therefore converge on one endpoint, while alternate endpoints cannot create a second writer over the same store. Diagnostic `probe` mode is read-only with respect to host state: it resolves existing aliases without creating a missing root, obtains the running version and recent-project catalog only through that live local protocol, and returns an empty recent list when no daemon answers. The explicit demo/test `seed` mode creates and canonicalizes its root, then acquires that same endpoint ownership before initializing or mutating `HostStore`, so it cannot race a live service generation.
- The Windows directory package completes with executable resource editing, embedded ASAR integrity validation, and `OnlyLoadAppFromAsar` enabled. A post-package check rejects a truncated PE image, stale Windows product metadata, missing required fuses, a main/preload/renderer or packaged-manifest mismatch, unexpected ASAR output, an empty ASAR, or a hostd copy that differs from the one built in that run. The native renderer also refuses to substitute browser-preview sample data if its context-isolated bridge is unavailable. Its packaged hostd passes a real named-pipe health exchange with exactly the implemented `snapshot_chunks_v1` and `runtime_integrity_v1` capabilities, `pairingIdentity.state: not_configured`, and no key-custody details. A bounded hidden launch then exercises the packaged main process, context-isolated preload, renderer, external hostd, runtime-seed argument, verified local health handshake, clean disconnection, and clean hostd/app exit. This development artifact is intentionally unsigned, its external hostd is not covered by ASAR integrity, and it is not a production installer or hostile-tamper-resistant distribution.

## Deferred production capabilities and release gates

- Remote SSH installation is a consent-bearing, non-executable plan. A signed, checksummed host-service installer/upgrader is not bundled, and no remote install command is executed by this build.
- A future Unix upgrader must stop every older lock-unaware hostd before starting this version. Empty ownership remnants intentionally fail closed and require bounded recovery guidance; mixed-version processes do not share the new sidecar fence.
- An interactive OpenSSH askpass bridge is not implemented. Existing system OpenSSH agent/key configuration can be used; password prompts are not surfaced by this desktop build.
- Native setup currently authorizes concrete aliases discovered from OpenSSH configuration. Arbitrary hostname/user entry remains a clearly labeled browser-preview demo until the desktop control contract can grant that target explicitly.
- Fresh resident-session provisioning remains unavailable. No production path creates the first durable resident binding for a new project/thread, so the existing-binding continuity checkpoint cannot yet deliver an out-of-box first run. Session creation must become a separate crash-safe host transaction that records its workspace/thread/generation authority before the gateway can advertise it. The RPC gateway remains diagnostic/fallback only because it owns and can complete its client-created session.
- Verified resident readiness and proof scheduling are isolated per exact binding. Healthy threads retain Prompt, Stop, and acknowledged-idle reconciliation while unrelated bindings fail, attach, disappear, or are replaced; removed and superseded prepared connections detach independently, and stale deferred attachments cannot publish. The public capability remains an aggregate host signal, so each command still requires the selected thread's exact live binding. Missing or failed bindings retry on later health polls but do not yet have durable quarantine state, bounded backoff, or a user-facing per-binding recovery record. Those lifecycle and recovery affordances remain required before production-scale multi-session control.
- Resident uncertainty retains its exact structured diagnostic beside the non-replayable desktop outbox barrier, and exact idle proof retires both. The renderer intentionally limits its global Attention projection to the newest 20 durable diagnostics, however, so an older still-active barrier can fall back to generic recovery copy under sustained multi-thread uncertainty. Before production-scale control, active resident diagnostics must be protected for the lifetime of their barrier or selected-thread lookup must bypass that presentation cap.
- A settled uncertain prompt or Stop has no safe automatic recovery in the pinned Prime Agent 0.7.0 protocol. `abort` and `waitForIdle` are not ordered against an older cross-client prompt preflight, while an abort whose transport outcome was lost may execute later and cancel newly admitted work. These barriers therefore remain non-replayable and nonretryable across restart. Safe operator recovery requires a future daemon-level atomic `abort_and_quiesce` epoch that covers admissions and pending preflights, or a verified session-rotation transaction that proves the old session can no longer mutate.
- The packaged-runtime initialization smoke still proves attested installation and model-catalog discovery with zero resident bindings. The separate release resident-attachment smoke now exercises the real pinned loader, harness-only resident creation, restart attachment, and authoritative projection without credentials. Before external release, verification must cover the production-wired client-owned escrow creation and promotion path, and an authorized provider-backed E2E must run one prompt and one Stop, observe their authoritative idle reductions, restart hostd, and prove that neither mutation is replayed.
- The verified runtime is now promoted from a packaged seed into a private installed development runtime, not an installed production-authorized runtime. Its embedded attestation deliberately says `development-integrity`: the outer artifact is unsigned, ordinary Node filesystem APIs cannot establish a race-free Windows reparse-point trust boundary, and same-user hostile modification is outside this checkpoint's assurance. The integrity manager rejects unsafe/ambiguous Windows names, links, extra files or directories, digest/tree/ABI drift, malformed pointers, corrupt finals, and uncertain publication; it copies only attested files into private staging, re-verifies before content-addressed publication or pre-use checks, recovers bounded crash leftovers, atomically rolls between exact attested images while retaining prior installs, and returns a frozen identity with no renderer-visible filesystem paths. Because an unsigned schema-valid prior pointer cannot be distinguished from same-user edits, rollover never dereferences it and is authorized only by the new build's embedded attestation plus exact seed; production transitions still require signed predecessor metadata. Repeated built-hostd smokes on August 6, 2026 returned initial health within the 3-second per-request gate and reached readiness within the 180-second gate; clean-promotion timing varied materially with storage and provider state, while restart re-verification retained the identical path-free identity. These observations are diagnostic, not release promises. Hostd keeps that work off its listener/health critical path; the desktop now polls and presents readiness, classifies a legacy hostd as `not_reported`, and package smoke uses the same production polling path. Fresh acquisition verification produces the opaque host-only handle consumed by runtime startup. Fresh resident-session startup, packaged real-binding upstream mutation/reduction E2E, code signing, a hostile same-user trust boundary, macOS/Linux, and additional architectures remain fail-closed release gates.
- The immutable upstream v0.7.0 release used by this checkpoint has a confirmed packaging defect in its Node distribution: the Amazon Bedrock provider references a bundle chunk that is absent from the official tarball. Digest verification correctly proves which bytes were installed, but cannot prove that every optional provider is operational. Amazon Bedrock therefore remains unsupported for this pin, and future runtime promotion requires provider-aware artifact smoke tests in addition to tree verification and daemon compatibility checks.
- Only `prompt`, `abort`, and the narrower `model.select` path have resident dispatch state machines. `steer`, `follow_up`, and `approval.resolve` remain rejected by the verified resident gateway until they gain equally durable, non-replayable operation-specific semantics.
- Before handoff is enabled, resident dispatch and authority movement must share one serialized lease/epoch boundary, admission must require the thread's current host location, and command plus handoff receipts must reserve one exact global identity namespace. Current handoff remains unavailable, so no source/destination authority move can race this local checkpoint.
- The current desktop command-identity ledger rewrites one bounded JSON file and deliberately rejects new identities after 10,000 entries while continuing to validate known identities. Before production-scale resident execution is enabled, replace it with a crash-safe indexed or sharded store that preserves the same permanent no-reuse invariant without an O(n) multi-megabyte fsync path or a reachable lifetime ceiling.
- Secure in-app ChatGPT subscription authentication is unavailable in production. The local protocol and main-process browser seam above are development-only; Prime Agent v0.7.0 has no injectable OS-keyring backend and its `AuthStorage` writes plaintext JSON. A production path requires host-owned OS-backed credential custody with verified access controls, durable OAuth attempt/receipt recovery across hostd and desktop restart, orphan-helper containment, and a renderer flow that labels ChatGPT subscription access separately from API-key billing. Headless SSH and relay sign-in remain unavailable until an independently reviewed device-code or equivalent remote-safe provider contract exists.
- The chunked snapshot path is integration-tested above the single-frame limit, including checksum corruption and out-of-order rejection. The current 8 MiB ceiling is deliberately aligned with shipped host/cache/process limits. Raising it to the specification's 50 MiB requires renderer/process stress evidence, file-backed reassembly, replay-from-cursor, transfer cancellation, pause/resume, bulk-channel preemption, and p50/p95/p99 release thresholds.
- Resident projection publication still writes a bounded full public snapshot plus catalog and lineage transaction at each accepted quiet boundary. Near-limit 8 MiB/2,000-message sustained-event write-volume and event-loop benchmarks, followed by block/delta storage if needed, are required before describing this path as token-live or fleet-scale.
- Native transport currently authorizes one active host target at a time. The v3 cache does retain bounded, separately stored per-host catalogs/snapshots and the renderer builds an authority-checked offline cross-host catalog, but only one host can be live and command-authoritative. Concurrent host transports, aggregate live-state semantics, resource bounds under many active hosts, and cross-host control verification remain Phase 1 gates; switching the active host must not be mistaken for production multi-host continuity.
- Cross-host handoff is unavailable. Handoff schemas and the isolated store harness cover verified clean durable checkpoints, but native cross-host commit is blocked. Before enabling it, command and handoff receipts must share one reserved `(deviceId, commandId)` namespace and every duplicate handoff must match the originally recorded handoff command exactly. Repository identity negotiation, Git object transfer, dirty/untracked state transfer, destination worktree materialization, and cross-host rollback coordination remain Phase 2.
- Native notifications remain deferred.
- Relay connectivity and mobile control are unavailable. The current acknowledged-prompt ownership correlation is deliberately device-local: the desktop retains its exact prompt envelope until the host's idle proof or completed reconciliation arrives, while another device has no matching outbox identity and cannot consume that completion. Host framed projection/proof signals are also suppressed on relay sessions. Cross-device Stop therefore requires a host-owned, generation-scoped monotonic control projection or operation-neutral idle epoch before it can be truthful; it cannot reuse the local desktop shortcut. Companion Preview presents follow-up and pairing as compact informational gates instead of disabled pseudo-controls. This build creates no QR code, matching code, credential, listener, relay session, or mobile command.
- Unix ownership races are covered by direct filesystem contention tests on the current Windows development host; real Unix-domain-socket/process integration must still pass in Linux and macOS CI before a cross-platform release.
- Real phone control remains Phase 3B: the cross-platform TLS-vs-Noise architecture spike and recorded lock decision, a reviewed crypto provider and application E2EE handshake, replay/sequence protection, private host/device key generation and OS-backed storage, human pairing confirmation, outbound host/desktop relay integration, durable multi-node relay grant issuance, compatibility handling, production channel lifecycle telemetry, and a packaged native mobile client must all be implemented and adversarially verified.
- Managed-compute adapters and later collaboration work remain Phases 4–5.

The Phase 0/Phase 1 protocol/UI foundation, existing-binding local resident checkpoint, and isolated Phase 3A seams are suitable for continued native integration and controlled development testing. The specification's production remote-release checklist is not satisfied. Fresh resident provisioning, remote SSH install/upgrade, cross-host handoff, relay connectivity, pairing, and phone control must remain unavailable until their release gates are implemented and verified.
