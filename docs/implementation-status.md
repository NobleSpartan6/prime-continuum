# Prime Continuim implementation status

This repository is a Phase 0/Phase 1 protocol and desktop-UI foundation for the seamless-remote specification, plus isolated Phase 3A security and relay primitives. It is not a production remote-agent release, and production resident commands that invoke a real provider are not authorized. On a release-attested local host, the native desktop can choose a workspace and provision a durable Prime Agent thread through client-owned escrow; exact projection publication gates the first Prompt/Stop capability. Over an already verified SSH bridge, a distinct path-free capability can create a new resident only in the selected thread's exact host-registered saved workspace, then reconcile status and End without remote path input. Focused Store/adapter/gateway/service/main/renderer suites verify provisioning and explicit End, including crash recovery, safe local folder reselection, SSH reference revalidation, same-workspace exclusion, stale reviewed-cursor rejection, uncertainty, and no mutation replay. The credential-free release lifecycle smoke drives the one Prime Agent runtime through model selection, Prompt, Stop, restart, and End without user credentials or provider network. The former separate Codex app-server preview and companion are retired: ChatGPT subscription OAuth now configures Prime Agent's own `openai-codex` provider. Remote SSH installation and upgrades, an installed two-machine lifecycle proof, cross-host handoff, relay connectivity, and mobile control remain deferred and fail closed. Packaging has been verified as an unsigned Windows x64 development artifact, an ad-hoc macOS arm64 development `.app`, and an unsigned read-only `.dmg` containing that app; Linux packaging, Developer ID signing, notarization, and installed macOS lifecycle remain unverified.

A notarized macOS DMG remains unverified; the current image is an ad-hoc local development artifact.

## Deferred production capabilities and release gates

- Remote SSH installation is a consent-bearing, non-executable plan. A signed, checksummed host-service installer/upgrader is not bundled, and no remote install command is executed by this build.
- The Windows development installer has no signed publication channel or automatic updater. Its real install, same-version repair, version upgrade, shortcut, running-hostd handoff, data-retention, and uninstall behavior still require isolated lifecycle E2E coverage before release; the checksum-only final-artifact gate deliberately does not execute setup or claim publisher authenticity.
- The complete authenticated-provider journey has not been run or cited. A local macOS development dogfood proved existing-account Sol execution, one RLM child, edits, tests, and `refine`, but did not perform the verified packaged-browser loop or publish a final-candidate receipt. The opt-in Windows installed-candidate harness encodes the no-tools lifecycle steps, while the separate packaged-macOS tool dogfood encodes exact Sol/RLM/browser correlation and owned-process cleanup; neither live lane has been run, and their mere existence and source tests do not satisfy this gate. Remote/headless OAuth remains unavailable until Prime Agent exposes an independently reviewed device-code or equivalent host-bound flow.
- A future Unix upgrader must stop every older lock-unaware hostd before starting this version. Empty ownership remnants intentionally fail closed and require bounded recovery guidance; mixed-version processes do not share the new sidecar fence.
- An interactive OpenSSH askpass bridge is not implemented. Existing system OpenSSH agent/key configuration can be used; password prompts are not surfaced by this desktop build.
- Native setup authorizes only concrete aliases discovered from OpenSSH configuration. Arbitrary hostname/user entry is not exposed until the desktop control contract can grant that target explicitly.
- Fresh local resident provisioning and explicit End are implemented behind `resident_lifecycle_v1`. The native picker gives only main/hostd the folder path; HostStore durably bootstraps canonical project/workspace/thread/generation authority before Prime Agent mutation; the coordinator uses `client_owned` creation, candidate escrow, one-way promotion, and stable projection publication before activating command capability. The path-free main ledger and renderer recovery surface reconcile restart, missing status, safe exact-folder reselection, definitive cleanup, committed projection refresh, and terminal quarantine without replaying create or promote. Verified SSH adds only saved-workspace provisioning: main refreshes the exact project/reference-thread projection, sends no path, persists the donor identifiers in its path-free ledger, and treats an uncertain submission as status-only. One serialized Store operation writes the registered bootstrap reservation and its exact `prepared` lifecycle as separate atomic records. A restart settles pending retirement first, then reconstructs only a missing local `prepared` record without invoking the gateway or provider; only status-proven `prepared`, `promoted_observed`, or `projection_committed` work may continue its exact coordinator operation. Unknown, dispatching, and quarantined states remain non-replayable. The same boundary blocks a competing local or SSH resident on that canonical workspace. Lifecycle compaction releases a reservation only after an exact transaction-bound release marker is durable; after lifecycle-operation removal, the pending retirement transaction revalidates and deletes only that released registered bootstrap so completed reservations do not consume the bounded bootstrap registry or startup scan. When that registry is full, only admission of another registered workspace may finish one eligible exact registered terminal retirement under the same Store lock before capacity is rechecked; local bootstrap admission never triggers compaction and local records remain retained. Restart converges before or after deletion, while the Bloom-style retired-ID fence remains the conservative replay denial and is not release authority. End is path-free and bound to the exact reviewed source cursor on local or verified SSH authority: cursor drift rejects before lifecycle WAL or side effects, while an admitted exact binding receives one-shot kill authority only after its ending record revokes command capability. A definitive acknowledgement preserves terminal task outcome and history, emits the exact public ended disposition, retires the binding and lineage, and returns the same completed result across restart. If that one kill loses its response, the operation remains non-replayable; it completes only when a read-only list from the same verified daemon proves the exact saved session absent or archived with no same-session replacement. Live, ambiguous, or unavailable daemon state stays quarantined. The legacy foreground RPC gateway remains diagnostic/fallback only because it owns and can complete its client-created session. An installed two-machine SSH Provision → Prompt/Stop → restart → End proof remains required; source and in-process tests are not that evidence.
- Verified resident readiness and proof scheduling are isolated per exact binding. Healthy threads retain Prompt, Stop, and acknowledged-idle reconciliation while unrelated bindings fail, attach, disappear, or are replaced; removed and superseded prepared connections detach independently, and stale deferred attachments cannot publish. The public command capability remains an aggregate host signal, so each command still requires the selected thread's exact live binding. Provisioning lifecycle failures have durable path-free recovery/quarantine records. The only automatic quarantine settlement is the narrow read-only End proof described above; every other quarantined or genuinely uncertain operation deliberately has no automatic unlock or retirement path. Failed pre-existing attachments also retry on later health polls without a bounded per-binding backoff policy. Those operator-recovery affordances remain required before production-scale multi-session control.
- Resident uncertainty retains its exact structured diagnostic beside the non-replayable desktop outbox barrier, and exact idle proof retires both. The renderer intentionally limits its global Attention projection to the newest 20 durable diagnostics, however, so an older still-active barrier can fall back to generic recovery copy under sustained multi-thread uncertainty. Before production-scale control, active resident diagnostics must be protected for the lifetime of their barrier or selected-thread lookup must bypass that presentation cap.
- A settled uncertain prompt or Stop still has no safe automatic recovery in the pinned Prime Agent 0.7.2 protocol. Upstream v0.7.2 repairs stale stopped-worker registrations during open/resume, but it does not add a cross-client admission/quiescence fence. `abort` and `waitForIdle` are not ordered against an older cross-client prompt preflight, while an abort whose transport outcome was lost may execute later and cancel newly admitted work. These barriers therefore remain non-replayable and nonretryable across restart. Safe operator recovery requires a future daemon-level atomic `abort_and_quiesce` epoch that covers admissions and pending preflights, or a verified session-rotation transaction that proves the old session can no longer mutate.
- The packaged-runtime initialization smoke still proves attested installation and model-catalog discovery with zero resident bindings.
